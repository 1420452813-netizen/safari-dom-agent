# 工程笔记

记录这套东西为什么长成这样，以及在 macOS 上做浏览器自动化会踩到的坑。不含任何具体站点的类名、域名或页面结构——那些属于 profile（见 README「适配到其它站点」）。

---

## 1. 为什么选 DOM 而不是像素

像素链路的每一环都在丢信息：截图 → 缩放 → 编码 → 模型识别 → 坐标反算。任何一环抖动（字体回退、窗口遮挡、Retina 系数、懒加载时机）都会变成不可复现的偏差，而最致命的是**无法回读**——你无法从一张图判断那个圆点是"已选中"还是"仅悬停样式"。

DOM 链路读的是属性，不是观感。代价是必须拿到浏览器的脚本执行权限，这在 macOS 上是个不小的门槛（见第 2 节）。

## 2. 执行通道：Apple Events 与 TCC

### 2.1 为什么需要独立 app bundle

宿主进程直接跑 `osascript` 时，TCC 会把「控制 Safari」的请求记在宿主（终端 / IDE / 沙箱容器）名下。沙箱环境下通常直接返回 `-10004`，且不会弹窗——用户连授权入口都看不到。

把执行体编译成**独立 app bundle**（`osacompile -o Runner.app runner.applescript`），它就有了自己的签名身份，首次运行会弹出「Runner 想要控制 Safari」，点允许即可，之后可反复从命令行触发。

### 2.2 关键坑：Runner 不能放在别的 app 包内

这是整个项目调试耗时最长的问题。同一份二进制（cdhash 完全一致）放到不同位置启动，结果不同：

| 启动路径 | 结果 |
| --- | --- |
| 独立目录下的 `x.app` | 正常 |
| `/tmp/x.app`、`~/Library/Application Support/<name>/x.app` | 正常 |
| `Host.app/Contents/Resources/x.app` | `-10004 未获得授权` |

原因：嵌套在宿主 app 内的辅助应用会被归入**宿主的 TCC 责任主体**。宿主自己没有授权、也不会替它弹窗，于是恒被拒——此时它在「系统设置 → 自动化」里根本不会出现，补 `CFBundleIdentifier`、重签名都没有用。

**结论**：包内那份只当种子，首次运行时 `ditto` 复制到用户目录再从那里启动。`ditto` 保留签名 → cdhash 不变 → 已有授权记录继续有效。

### 2.3 签名：不要用 `codesign --deep`

`--deep` 会递归重签嵌套的辅助 app，改变其 cdhash。cdhash 一变，用户此前授予的自动化权限随即失配，表现为**升级一次就再也连不上浏览器，且不再弹窗**。

正确做法是逐层签：先签 `Contents/MacOS/` 下的可执行文件，再单独签外层，嵌套辅助 app 保留出厂签名。

## 3. 事件生命周期：写给 SPA 看

直接改 `input.value` 对现代框架无效——它们监听的是事件，不是属性。完整顺序：

```
focus → 设值（走原型链 setter）→ input → change → blur
```

要点：

- 用 `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set.call(el, v)`，绕过框架可能重写过的实例 setter，否则赋值会被框架的脏检查忽略。
- `contenteditable` 元素没有 value 属性，改 `innerText`。
- 事件必须 `bubbles: true`，委托在根节点上的监听器才收得到。
- 单选/多选的"取消选中"不能靠 `checked = false`，要 `click()` 一次让它自己走状态机。

## 4. 回读断言

写入不等于生效。`apply` 结束后必须重新读一次页面，把每题的当前状态与目标比对，不一致重试一次，仍不一致就列入失败清单并如实上报——**不要静默通过**。

统计成功率时也要用回读结果算，而不是用写入函数的返回值：后者对「已选中但答案变更」这类情况容易误判。

## 5. 坐标与物理点击

部分元素（尤其是 `<a>`）只认真实鼠标事件，`el.click()` 无效。此时要换算屏幕绝对坐标：

```
screenX = window.screenX + rect.left + rect.width / 2
screenY = window.screenY + (outerHeight - innerHeight) + rect.top + rect.height / 2
```

`outerHeight - innerHeight` 就是浏览器 chrome 的高度（地址栏 + 标签栏），漏掉它会整体偏移一个 chrome 高度。

**禁区校验**：当窗口被移动、缩放或跨屏时，换算结果可能落到页面之外，一按就是误触。派发前先用窗口几何校验矩形是否完整落在可视区，越界则改用 DOM 事件或滚动到可视区后重算。

## 6. 编码：一条容易踩两次的链路

AppleScript 的 `write` 用系统主编码落盘（中文环境常见 GBK），Python 按 UTF-8 读会乱码。两个兜底：

1. **JS 输出纯 ASCII**：把非 ASCII 字符转成 `\uXXXX`，让结果文件只含 ASCII，整条链路对编码免疫。
2. **读取侧多编码兜底**：`utf-8 → gb18030 → mac_roman → latin-1` 逐层尝试。

## 7. 并发推理与结构化输出

- 线程池并发，结果按题目顺序回填；`usage` 计数要加锁。
- 要求模型「只输出 JSON」会降低准确率——先让它分析，再输出 JSON（CoT）。
- 模型常带 Markdown 围栏或重复 JSON。用 `json.JSONDecoder().raw_decode()` 取第一个完整对象，比贪婪正则 `\{.*\}` 稳，后者会把围栏副本一起吞进去。
- 提示词里如果有 `{"answer":"A"}` 这种字面量，不能用 `.format()` 拼接（花括号会被当占位符），用 `.replace()`。
- 单个通道偶发 `-10004` / 超时是常事，通道内重试一次再回退，比直接失败友好。

## 8. 空返回值的坑

注入脚本调用页面函数（如 `openConfirm()`）时没有返回值，执行器会写出一个空文件。若读取侧把「空文件」当作「还没出结果」继续轮询，就会一直等到超时，并误报成权限问题。

处理：文件存在但内容为空 → 稍等复查一次 → 仍为空则视为「执行成功、无返回值」，返回空串。

## 9. 基准怎么测才可信

- 同一份页面、同一台机器、多轮取均值 ± 标准差；换卷换机器后不要和旧数据混着比。
- 分别记录各阶段耗时，不要只报端到端——否则不知道该优化哪里。
- Token 用 API 返回的 `usage`，不要估算。
- 成功率要用回读结果算（见第 4 节）。
- 指标下降也要如实写进表格并解释原因，只挑好看的指标一眼就会被看穿。

## 10. 调试清单

| 症状 | 优先怀疑 |
| --- | --- |
| `-10004` | 执行体位置（是否在宿主 app 包内）→ 授权是否失效（是否重签过） |
| 点了没反应 | 是否走了 DOM click（`<a>` 无效）→ 窗口是否在最前 |
| 读到 0 题 | profile 的 `containers` 与页面实际结构不符 |
| 读到题但题干为空 | `stemTitle` 未命中，且 `stemStrip` 剔得过多 |
| 回填 false | 元素不是标准 `input`，或事件未 `bubbles` |
| 结果乱码 | 编码链路（第 6 节） |
| 偶发超时 | 空返回值（第 8 节）或实例复用 |
